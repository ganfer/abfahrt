# Smartphone screenshot

The README preview is generated by `.github/workflows/widget-screenshot.yml`.

## Why the preview is rendered separately

Scriptable is an iOS runtime and cannot be executed natively on GitHub's Linux runners. The pipeline therefore does **not** claim to be an iOS simulator. Instead, `scripts/render-widget-preview.mjs` reads the current `DEFAULT_WIDGET_CONFIG` from `VagAbfahrten.js` and builds a deterministic smartphone-sized HTML representation of the compact widget.

This keeps the preview coupled to the current default column visibility, widths, spacing, badge height and font sizes without requiring a TRIAS key, GPS access or live network data.

## Pipeline behavior

On pull requests that change the widget runtime, Config, renderer or screenshot workflow, the job renders a fresh PNG and uploads it as a workflow artifact for visual review.

On pushes to `main`, the same image is written to `docs/assets/widget-preview.png`. The workflow commits the PNG only when its bytes actually changed, so screenshot-only commits do not create a workflow loop.

The README references that versioned PNG directly.

## Preview data and limitations

The preview uses fixed demo departures and a fixed clock. It never calls EFA-BW/TRIAS and never reads secrets. Realtime, delay, timetable-only and cancelled states are intentionally represented in the fixture so the main visual states remain visible.

The generated image is a documentation preview, not a pixel-perfect iOS screenshot. Final visual behavior still depends on Scriptable and the actual iPhone/widget size. Changes to rendering logic that are not represented by the default layout values may require an accompanying update to `scripts/render-widget-preview.mjs`.
